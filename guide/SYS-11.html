    Inventory & Tools

    SYS-11

    Summary

    A Bag with no slot limit, stacking, item order, Quick Slots, and the effects of using Tools and Potions.

    Rules

    • An item that is being worn is not in the Bag (it is in Equipment).

    Stacking

    • The Bag has no slot limit: every item that enters the Bag is always accepted in full. There is no "Bag full" state.
    • An item goes into a matching stack (same id and upgrade_level) that has not reached max_stack (ItemData); the remainder opens a new slot.

    Order, Quick Slots, and Discarding

    • Bag order: type (Weapon, Armor, Food, Potion, Tool, Stone, Material) → higher rarity → name (tr of the name key) → higher upgrade_level → larger amount → uid. The Bag is always sorted automatically; there is no manual sorting.
    • Quick Slots: 4, for Food and Potions; each slot stores an item ID, not a copy of the item. One ID may be in only one slot: placing an ID in another slot moves it out of its previous slot. A filled slot can be emptied (Bag screen). Using a slot removes 1 from a matching stack in the Bag (Bag order above). If that item is no longer in the Bag, the slot keeps the ID and is shown with a count of 0 (it cannot be used) until a matching item enters again or the player changes its contents.
    • Removing one ID (eating, drinking a Potion, using a Tool, recipe materials) takes from the last stack in Bag order, which is the smallest stack, and then goes back to the previous stack if more is needed. Example: stacks of 99 and 3, remove 2 → 99 and 1; remove 5 → 97. Exception: Rules.
    • Items of type MATERIAL/ELEMENT_STONE are recorded in codex_items every time they actually enter the Bag, from any source (picked up, gathered, crafted, reward), without duplicates (Materials). Moving an item between the Bag and Equipment is not "entering the Bag".
    • Discarding an item always asks for confirmation.

    Using Potions

    • Drinking a Potion (from the Bag or a Quick Slot) uses 1 PotionData item (PotionData) and does not change Hunger. There is no cooldown between Potions.
    • Potion buff: buffs with the same id do not stack; drinking again resets its timer; the duration uses the INT formula in Derived Stats.
    • Order of effects (same as eating, Eating (Outside Cooking)): the item is reduced by 1 (smallest stack), the buff is applied, then HP increases by hp_restore_pct % of max HP and Stamina increases by stamina_restore_pct % of max Stamina, each rounded down and then clamped to the max value after the buff.
    • Allowed when HP and Stamina are full: the item is still consumed (same as eating at Hunger 100).
